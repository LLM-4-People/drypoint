# Architecture

A static PWA: no runtime server, no bundler or compile step, no dependencies.
The generated precache manifest and the worker's build stamp are the only build
artifacts. The browser loads ES modules from `src/` and talks to the printer
through Web Serial or Web Bluetooth. `sw.js` plus the generated
`assets/precache.js` make the whole app work offline.

## Data flow

### Editing

```
pointer / keyboard / inspector
        ↓
editor/controller.js        validate + clamp, push history
        ↓ onChange
main.js saveDocument()      debounced localStorage write
        ↓ rerender
label/render.js             paint at native printer dots
editor/canvas.js            copy to the visible canvas + overlay
```

`controller.document` is the single in-memory source of truth. Every mutation
passes through `validateDocument`/`clampElement`; a locked element rejects
geometry and content edits at that one choke point.

### Rendering and printing

```
controller.document
   ↓ renderDocument(document, { dither, threshold })
canvas at head width × length in printer dots
   ↓ canvasToRaster (fixed 128 luminance cut)
{ width, height, rows: Uint8Array[] }
   ↓ device.print(raster, { copies, lengthMm, signal })
print-options.js → density, labelType, speed, copies
   ↓ print-job.js
frames (0x85 / 0x84) → protocol/client → session → transport
```

Images are decoded before painting (`hydrateImages`); a failed decode fails the
print instead of printing a hole. The user threshold drives image dithering
only; the final raster cut is fixed so small antialiased text stays legible.

### Device discovery

```
manager.connect()
  → transport candidate (serial or BLE) → Session
  → statusData, heartbeatInfo, capabilities, heartbeatAdvanced
  → GetInfo probes (model, serial, density, label type, auto shutdown,
    battery, firmware, hardware)
  → rfid roll tag
  → mergeCapabilities()
  → setGeometry() (reported head width / dpi-class pitch / max length)
  → applyDetectedSettings() (density, tape type)
  → 'discovered' event → UI re-render
```

The seven GetInfo keys with no automatic consumer (job speed, head width,
accuracy, language, Bluetooth address, printer print mode, print area) are
never probed by discovery; the Print panel's "Read device info" action reads
them on demand under the same deadline.

At least one core probe (`statusData`, `heartbeatInfo`, `capabilities`) must
answer, otherwise `connect()` fails and the manager reports `error`. The
session and client are captured once per discovery, so a reconnect mid-probe
cannot mix two sessions; an optional probe that is unsupported or times out
yields `null`, while a fatal link error rejects the connect instead of
publishing a half-read model. "Connected" is only published after the session
that answered is confirmed to be the current, open one.

Discovery is single-flight per session: `connect()`, `refresh()`,
`resetPrinter()` and the post-print refresh share one promise, so two callers
can never publish two models (the later-finishing, older one would win). The
whole pass has one deadline (`CONFIG.protocol.timeouts.discovery`, 12 s) passed
as an `AbortSignal`; when it fires, the in-flight exchange is aborted and the
caller gets "The printer did not finish discovery within 12000 ms" instead of a
minute-long lock.

A group this pass did not report falls through to the model the same session
already published (`mergeCapabilities({ previous })`), one rule per group: one
unanswered TLV must not reset `hasVolume`, `speedRange`, `labelTypes` or the
device's `maxLengthMm` to a default. `previous` is only supplied when the
session is still the published one, so a new connection never inherits the
previous printer. `applyDetectedSettings` runs inside discovery before the
`discovered` event, so the panel renders the mirrored density rather than the
value it had before the connection.

Disconnecting (or losing the link) clears the readings that belonged to it —
battery, sensors and the roll tag, with their `source` entries reset to
`default`. Identity, learned features, geometry and the mirrored settings stay,
so the panel keeps the model while the live rows stop claiming to be current.

`connect()` owns a generation counter: if `disconnect()` runs while the
transport is still opening, the attempt is cancelled, its transport is closed,
and no discovery or reconnect follows.

A print job's post-print refresh runs *inside* the job lock: `printing` stays
true, `currentJob` is cleared, and `discover()` runs directly (not `refresh()`,
which asserts idle) until it settles, so probe frames never interleave with the
next job's rows. The same refresh runs after a failed or cancelled job.

### Android shell (APK)

```
android/app/src/main/java/.../MainActivity.java
    WebView over https://drypoint.local; shouldInterceptRequest serves
    assets/www with the right MIME types. No HTTP server, no cleartext.
android/app/src/main/java/.../BleBridge.java
    scan → connect → enable notifications → chunked writes at the
    negotiated MTU; UUIDs and name prefixes arrive from src/core/config.js.
    The connect call settles once notifications are on *and* the MTU exchange
    finished (or 300 ms passed); each chunk waits for its ack, and a missing
    ack closes the link instead of guessing. Teardown is guarded, so a
    destroyed Activity is never called into.
src/device/transports/android.js
    bridge → the same Transport contract as serial/BLE; every bridge call has
    its own timeout and close() rejects whatever is still pending.
scripts/build-android.mjs
    aapt2 → javac → d8 → zipalign → apksigner; assets are copied from
    assets/precache.js, never a hand-written list.
```

The WebView origin is stable (`https://drypoint.local`), so `localStorage` survives
app restarts. The service worker is skipped inside the shell: the assets are
already local, and a worker cache would outlive an APK update.

## Document model

Documents are plain JSON, authored in printer dots, landscape (the long axis is
the tape length).

```json
{
  "version": 4,
  "name": "Untitled",
  "lengthMm": 40,
  "copies": 1,
  "elements": [
    {
      "id": "text_...",
      "type": "text",
      "x": 4, "y": 17, "w": 312, "h": 62,
      "rotation": 0, "locked": false, "visible": true,
      "text": "Hello", "fontPx": 0, "bold": true,
      "align": "center", "valign": "middle"
    }
  ]
}
```

Element types and their extra fields:

| Type | Fields |
| --- | --- |
| `text` | `text`, `fontPx` (0 = auto), `bold`, `align`, `valign` |
| `qr` | `value`, `ecLevel` (`L`/`M`/`Q`/`H`) |
| `barcode` | `value`, `symbology` (`code128`), `showText` |
| `image` | `src` (data URL), `fit` (`contain`/`cover`/`stretch`), `dither` (`auto` or a dither mode) |
| `rect` | `strokePx`, `filled`, `radiusPx` |

Validation (`validateDocument`) clones its input, clamps `lengthMm` to the
active geometry limits (20–200 mm, or the device maximum), clamps `copies`
1–99, drops unknown element types, generates ids for falsy or duplicate ids,
validates every enum, clamps geometry, and allows an empty `elements` array.
`createDocument` is the only owner of the first-run "Hello" element; it clamps
the length *before* it sizes the seeded frame.

Text has no width-based word wrapping: `\n` is the only line break. Auto-size
shrinks the whole block to fit the box, down to `autoFontMinPx`; a line that is
still too wide shrinks no further and is reported as "Text does not fit its
box" rather than silently reflowed (`test/render.test.mjs` pins this).

A document may also carry `notices`: operator-facing strings left by a
migration that had to grow the tape or drop content the printer cannot hold
(e.g. a legacy barcode with non-ASCII text). Notices are part of the label, not
of one render, so `renderDocument` includes them in its warnings and they reach
the same print confirmation as any layout problem.

`renderDocument` runs one layout-warning pass before painting. It reports
visible elements whose boxes overlap (a frame or background rect that fully
contains another element is intentional and skipped) and barcodes or QR codes
whose box is below two dots per module. The pass reports only; it never moves,
grows or shrinks an element, because a silent re-fit would change the label the
operator authored.

Migration:

- **v4** is the current landscape model.
- Older documents are migrated with `x' = y`, `y' = headWidth − x − w`,
  `w' = h`, `h' = w`, `rotation' = rotation + 270°`. This pair matches the
  existing rotation convention; it is pinned by `test/schema.test.mjs`. Only a
  finite number or a non-empty numeric string counts as a version: `''`,
  `'   '`, `true` and `[]` are not versions and are treated as the current
  model instead of being rotated as portrait v3.
A document saved under a newer version is reported, never silently coerced.
There is no migration from the pre-release application name: the storage
namespace is new, so no old key is read and no compatibility shim exists.

## Capability model

`mergeCapabilities` combines, in this precedence:

1. capability TLV (`0xBF`) — feature switches, ranges, head width, dpi
2. heartbeat info (`0xDE`) — versions, head width, RFID flags
3. heartbeat advanced (`0xD9`) — battery, sensors
4. status data (`0xB5`) — protocol build, colour support
5. `GetInfo` keys with a declared consumer — density, label type, auto
   shutdown, battery and identity/version fields
6. roll tag (`0x1B`) — SKU, capacity, remaining labels

`INFO_PROJECTION` in `device/manager.js` is the one table for the `GetInfo`
keys: a key is probed only when a capability consumes it. Keys nothing consumes
(job speed, head width, accuracy, language, Bluetooth address, print mode and
print area) are diagnostic-only and are read on demand by the Print panel's
"Read device info" action, under the same discovery deadline. The capability
TLV raw stays available in the "Read capabilities" diagnostic, which is also
where the colour and gray TLVs remain inspectable; the panel itself has one
honest "Output: 1-bit monochrome" row.

Each group records `source: 'reported' | 'default'`; the Print panel shows
assumed groups explicitly. A group this pass did not report keeps the same
session's previous value and source (see Device discovery), so a silent probe
never resets a feature to a guess. Absent TLV booleans are `null` so the merge
can fall through instead of treating "unreported" as `false`; a boolean TLV
must also carry at least one byte, so a zero-length value is unreported rather
than "no". `hasRtc`, `hasVolume` and `hasCutter` keep that `null` all the way to
the UI: "reported yes", "reported no" and "not reported" are three different
states (`capabilityState`). Colour and gray are protocol facts with no control
and no merged field: they stay in the "Read capabilities" diagnostic next to the
one honest "Output: 1-bit monochrome" row. A short `0xD9`
decodes as `null`, so an all-undefined sample can never become a sensor
reading. A TLV range whose `max` is below its `min` decodes as absent, so
nothing can clamp against a backwards range.

Consumers:

- `models.js` is the only printer-model table. `0x0910` (D110_M) is confirmed,
  `0x0210` (D11_H) is experimental, every other known id is named and marked
  unsupported, and an id outside the table is `Unknown`. The task is a model
  fact (`D110M V4`), never a name derived from the protocol build.
- `geometry.js` takes the reported head width and the dpi class. The pitch is
  `dpi / 25.4` — 203 → 7.99, 300 → 11.81 dots/mm — and `widthMm` is derived
  from the head; the configured 8 dots/mm is only the fallback when no usable
  dpi was reported. `geometry().reported` is derived from
  `source.geometry === 'reported'`, which requires the head width itself, never
  a finite fallback width.
- `print-options.js` clamps density to the reported range and picks a supported
  label type. A malformed range yields the fallback, never `NaN`.
- `printBlockReason` refuses a job, before the first frame, when the resolved
  model is unsupported (naming it), when the model is unknown or absent, or
  when the head width is a guess (`geometry().reported === false`, including a
  malformed 0/65535 report). An experimental model is allowed only after the
  one pre-print confirmation says it is experimental. Lid, paper and battery
  are then refused only when the printer actually reported them, and they run
  on the print job's own fresh heartbeat (`applyHeartbeatSample`) inside the job
  lock. When the printer reported sensors but the job's heartbeat goes
  unanswered, the gate refuses the job: "no answer" is not "all clear".
- The UI gates Sync clock on `hasRtc`; the sound switches stay disabled and
  marked unknown until a successful read, and revert on a failed write; auto
  power-off shows "Not reported" until the printer reports a value. The density
  and tape-type controls take their range/options from the capability model,
  while the settings schema owns their label and option text.

## Storage keys

All keys share `CONFIG.app.storagePrefix` (`drypoint`).

| Key | Shape | Owner |
| --- | --- | --- |
| `drypoint.document` | the document JSON above | `main.js` (`loadDocument`/`saveDocument`) |
| `drypoint.settings` | `{ version: 4, data: { ...settings } }` | `core/settings.js` via `core/store.js` |
| `drypoint.rolls` | `{ version: 1, data: { profiles: { [barcode]: { lengthMm, labelType, updatedAt } } } }` | `device/roll-profiles.js` |
| `drypoint.zoom` | a number as a string | `main.js` |

Settings are validated on every load: unknown keys are dropped, enums fall back
to defaults, numbers are clamped, and a read/write failure is logged instead of
being silently treated as success. Roll profiles are sanitised when written and
the map is bounded by `CONFIG.device.maxRollProfiles` (64), evicting the least
recently updated entry.

## Offline strategy

`scripts/precache.mjs` is the single owner of the file list, of the app-surface
allowlist and of the structural anchors. It walks:

- `index.html` `src`/`href` references (stylesheet, manifest, icons, classic
  scripts, module entry),
- the ES module import graph rooted at `src/main.js` (one shared lexer decides
  what is a comment, a string, a template or a regex; comment text and string
  literals are not dependencies),
- every icon declared by `manifest.webmanifest`,
- local `url()` assets in every collected stylesheet (`data:`, `http(s):`,
  protocol-relative and fragment references are skipped),
- the anchors in `REQUIRED_FILES`.

Every candidate passes `isAllowed()` after `resolve()` canonicalises it. The
allowlist is `index.html`, `manifest.webmanifest`, `assets/**` and `src/**`; a
reference such as `assets/../android/keystore/…` is judged as
`android/keystore/…` and rejected. `syncAssets()` in the Android build and the
dev server's served set call the same function, so there is no second copy of
the rule and no generic static fallback.

It emits `assets/precache.js`:

```js
self.__PRECACHE = {
  version: '<sha256 prefix>',
  required: ['index.html', '…'],
  files: ['…'],
  digests: { 'index.html': '<sha-256 of the file bytes>', '…': '…' },
};
```

`required` is generated from `REQUIRED_FILES`; `sw.js` validates against
`MANIFEST.required` and keeps no copy of the list. `digests` has exactly the
same keys as `files`.

The list is sorted and the version is a deterministic content hash over every
runtime file. The same hash is written into `sw.js` as its `BUILD` stamp.
`--check` exits non-zero when either generated file differs; `--write`
regenerates both, each file replaced atomically on its own. The pair is not
written as one transaction: if a crash lands between the two renames the files
disagree, and the worker rejects that install (`MANIFEST.version !== BUILD`)
instead of serving a half-updated list. `scripts/serve.mjs` runs `--write`
before listening, so development never serves a stale list.

The stamp is what makes an asset-only deploy install a new worker: the browser
fetches `sw.js` on every update check, sees a changed `BUILD` line, installs the
new worker, and that worker imports the matching manifest. The worker also
rejects an install when its stamp and the manifest disagree. `main.js` registers
with `updateViaCache: 'none'` so neither the worker nor its imported manifest is
served from a stale HTTP cache.

`sw.js`:

- imports the generated manifest (`importScripts('assets/precache.js')`),
- installs by fetching every listed URL into a **staging** cache, rejecting
  redirected responses, any content type that contradicts the file extension
  (a host that rewrites 404s to `index.html` must not be cached as a module),
  and a known extension served without a `Content-Type`,
- hashes every staged body with `crypto.subtle.digest('SHA-256', …)` and
  compares it with the manifest digest; a mismatch or a missing digest fails the
  install before promotion,
- promotes into the live cache only after every file arrived and matched; a
  failed install — including a same-build reinstall — leaves the active cache
  untouched,
- rejects the install with a console error plus a `precache-error` message to
  every window when anything is missing, duplicated, redirected, mistyped,
  tampered with, or omits a structural anchor; the page shows that message as a
  toast and logs it,
- names the cache from the build hash and deletes older `drypoint-*`
  caches on activate,
- serves precached URLs cache-first (a cold start with no connectivity paints),
- serves navigations network-first, falling back to the cached `index.html`
  when the network fails *or* answers a non-OK status,
- never answers a non-navigation request with `index.html` and never
  content-type-checks a navigation.

`npm run check:precache` and `test/precache.test.mjs` fail when the graph, the
generated manifest, or the worker stamp disagree.

## Logging

`src/core/log.js` is the only module that touches `console`. It owns:

- level filtering (`trace`…`error`) and the settings-driven level,
- a bounded ring buffer (`CONFIG.log.bufferSize`, 1000 entries),
- redaction of secret-shaped detail keys (`CONFIG.log.redactKeys`) and of
  `Bearer …` / `user:pass@` strings,
- byte truncation for binary details (`CONFIG.log.maxBytesShown`),
- `getLogEntries`/`subscribeLog` for the diagnostics viewer,
- `exportLogReport` for the downloadable JSON bundle.

Modules create scoped loggers (`device`, `device.print`, `protocol.client`,
`ui.print`, …) so a log line identifies its owner without ad-hoc formatting.

`sw.js` is the one documented exception: a service worker cannot import the app
logger, and its install failure must be visible even when the page never loads.
It reports through `console.error` and posts a `precache-error` message that the
page logs and shows (see Offline strategy). No other module calls `console`.

## Dev server and operations

`scripts/serve.mjs` serves exactly the app surface with no dependencies: the
files listed by `assets/precache.js` plus `sw.js`. It binds to `127.0.0.1` by
default; `--host 0.0.0.0` is an explicit LAN opt-in. Repository files outside the
app surface (keystore, docs, scripts, tests, `.run`) answer 404, so a LAN bind
cannot expose the signing key. The pid file is `.run/server-<port>.pid` and
contains JSON:

```json
{ "pid": 1234, "port": 8080, "startedAt": "2026-11-14T19:59:07.605Z" }
```

A start refuses to run when that file tracks a live `serve.mjs` process for the
same port, and replaces stale or unrelated pid files. `scripts/stop.mjs` reads
the file, checks the pid, the port and the process command, sends `SIGTERM`,
waits up to five seconds, and only then removes the file. A refusal or timeout
leaves the file in place and exits non-zero.

## Releasing

`package.json` is the one owner of the version. A release is a tag that proves
itself: `v<version>` on a commit in `main`.

1. Change `package.json` and add the matching `CHANGELOG.md` section in the same
   pull request. The section heading is exactly `## [<version>] - YYYY-MM-DD`.
2. Merge to `main`. `Checks` runs on the push; its aggregate job `required` is
   the only required status check.
3. Tag that commit and push the tag:

   ```bash
   git tag v1.0.0
   git push origin v1.0.0
   ```

4. `.github/workflows/release.yml` runs on the tag only:
   - `npm run verify` is the same gate a pull request passes — brand, precache,
     privacy, tests, docs and workflow policy — so a tag cannot publish a red
     commit;
   - `node scripts/release-notes.mjs --tag "$GITHUB_REF_NAME"` fails unless the
     tag is exactly `v<package.json version>` and the changelog has that section;
   - `ANDROID_KEYSTORE_BASE64` is decoded into `$RUNNER_TEMP`, the password and
     alias come from secrets, and `CI=true` makes a missing key a hard failure;
   - the signed APK is copied to `dist/drypoint-<version>.apk`, hashed into
     `dist/drypoint-<version>.apk.sha256`, attested with
     `actions/attest-build-provenance`, and uploaded as an artifact;
   - `git diff --exit-code` proves the build changed no tracked file;
   - the `publish` job — the only job with `contents: write` — downloads the
     artifact and runs `gh release create "$GITHUB_REF_NAME" --verify-tag` with
     the APK, the checksum and the notes file. A tag containing `-` is a
     prerelease; every other tag is `--latest`. There is never a draft.

   A concurrent release is serialised by `concurrency: release` with
   `cancel-in-progress: false`.

The Pages deployment is separate. `.github/workflows/pages.yml` runs on every
push to `main` — never on a tag — stages `_site/` from `collectFiles()` plus
`sw.js`, the generated `404.html` and `.nojekyll`, and smoke-tests the deployed
`/`, `/sw.js`, `/manifest.webmanifest` and `/assets/precache.js` for a 200, with
the manifest required to be served as `application/manifest+json`.

Every workflow pins each action to a commit SHA, declares explicit
`permissions`, a `concurrency` group and a job `timeout-minutes`, and sets
`persist-credentials: false` on every checkout. `npm run workflows:check`
enforces that policy locally and in CI; `actionlint.yml` runs the pinned
actionlint for the YAML and expression rules a script cannot see.
